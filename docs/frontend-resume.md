# 화면 이탈 후 이전 분석 다시 보기

팀장님이 구현할 프론트 인수 조건이다. 백엔드는 화면 이탈과 무관하게 접수된 작업을 실행하고, 같은 job ID 조회로 진행 상태와 결과를 반환한다. 이 문서 작성으로 프론트 코드나 Vercel을 변경하지 않았다.

## 사용자 흐름

1. 사용자가 링크를 제출하고 접수에 성공하면 작업 ID와 결과 조회 토큰을 함께 보관한다.
2. 탭을 닫거나 다른 페이지로 이동해도 서버 작업은 계속된다. 화면 이탈 시 프론트의 polling만 중지한다.
3. 같은 브라우저·같은 출처로 돌아오면 홈에서 **이전 분석 보기**를 제공한다.
4. 선택하면 새 분석 POST 없이 기존 작업 GET을 호출한다. 진행 중이면 polling을 재개하고, 종료 상태이면 저장된 결과/실패 안내를 보여준다.

## 보관할 값

현재 MVP는 마지막 분석 한 건의 복원으로 구현한다. 계정별 이력·다른 기기 동기화와 구분한다.

`localStorage`의 버전이 있는 키(예: `chamsae.analysis.v1`)에 `job_id`, `job_access_token`, `session_id`, 저장 시각을 하나의 레코드로 보관한다. `sessionStorage`만 사용하면 탭을 닫았다가 재방문하는 조건을 충족하지 못한다. 접수 응답을 받은 직후, 결과 화면으로 이동하기 전에 기록한다. 다른 분석 접수가 실패했다고 이전 레코드를 지우지 않는다.

조회 토큰은 그 작업을 읽을 수 있는 자격이다. URL·쿼리·공유 링크·로그·분석 SDK 이벤트에 넣지 않는다. 결과 전체나 영상 파일을 저장할 필요는 없다. Cloudflare Service Secret과 `PUBLIC_GATEWAY_KEY`는 브라우저 저장소에 넣으면 안 되는 서버 전용 키이며 이 조회 토큰과 다르다. 렌더링할 외부 제목·근거를 HTML로 직접 삽입하지 않는다. localStorage는 HttpOnly가 아니므로 같은 출처 스크립트가 읽을 수 있는 범위임을 전제로 한다.

스토리지 접근 실패/손상은 화면 오류로 만들지 않는다. 현재 탭에서는 메모리로 결과 조회를 이어가되, 재방문 복원이 보장되지 않음을 안내한다. 구형 `conan.session`에 job ID만 남아 있으면 공개 조회 권한이 없는 상태다. ID만으로 새 토큰을 만들거나 세션 목록 API로 복구하려고 하지 않는다.

## API 계약

- 같은 출처 `POST /api/analyze`: `url`, 선택 `session_id`, `turnstile_token`을 전송한다. 응답의 `job_id`, `job_access_token`, `session_id`를 보관한다.
- 같은 출처 `GET /api/jobs/{job_id}`: `Authorization: Bearer <job_access_token>`을 전달한다. Vercel Function이 서버 인증 정보를 추가한다.
- 재방문 조회에는 Turnstile 토큰이나 새 분석 POST가 필요하지 않다. 만료된 조회 토큰을 갱신하는 API는 현재 없다.
- `completed`, `completed_with_limitations`, `failed`, `timed_out`이면 polling을 종료한다. 상태별 화면은 [API 계약](api-reference.md)을 따른다.
- 404 또는 로컬에서 명백히 만료된 토큰이면 복원 레코드를 정리하고 “이전 분석을 더 이상 확인할 수 없습니다”와 새 분석 동작을 제공한다. 자동으로 분석을 재접수하지 않는다.
- 429는 `Retry-After`를 따르고, 통신 실패/5xx에서는 저장 정보를 지우지 않고 재조회 동작을 제공한다.

## 보장 범위

조회 토큰은 발급 후 24시간 유효하다. **결과를 반드시 24시간 보관한다는 뜻은 아니다.** 완료 결과는 보관 개수 상한(코드 기본 200건)에 따른 정리, 키 교체 등으로 더 일찍 조회되지 않을 수 있다. 서버 GET 응답이 최종 기준이다.

동일한 브라우저 프로필·사이트 출처에 저장 데이터가 남아 있어야 한다. 시크릿 창 종료, 사이트 데이터 삭제, 기기/브라우저 변경, 도메인 변경은 자동 복원 범위 밖이다. 서버의 완료 결과는 영속 볼륨에서 복원하지만 실행 중 작업은 갑작스러운 서버 장애 후 이어 실행하는 기능이 없다. 정상 배포는 drain으로 작업 종료를 기다린다.

## 팀장님 완료 검수

- 분석 접수 후 탭 종료 → 같은 사이트 재방문 → 이전 분석 보기 → 진행 상태 또는 완료 결과 조회.
- 결과 페이지 새로고침과 작업 종료 후 재방문에서도 같은 결과 조회. 재방문만으로 POST가 추가되지 않음.
- 토큰 누락·변조·만료·작업 정리 404를 안전하게 종료하고, 429/일시 네트워크 오류 때 저장 정보를 보존함.
- 브라우저 기록·분석 SDK·로그·URL에 조회 토큰 및 서버 비밀키가 남지 않음.

아직 실제 프론트에서 검수하지 않았다. 서버의 정상 토큰 200·변조 404 검수와 프론트 재방문 E2E를 구분한다.
