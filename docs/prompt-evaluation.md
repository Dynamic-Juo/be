# 프롬프트 설계와 평가

기준일: 2026-09-10. 현재 프롬프트 버전은 `2026-09-10.3`이며 정의는 [prompts.py](../deepcheck/prompts.py)에 있다. 제품 판단 기준은 [docs PR #6의 evidence-policy](https://github.com/Dynamic-Juo/docs/blob/35df85c985cddee485db71fe6501edacbf98515d/design/evidence-policy.md)를 따른다.

## 두 LLM 작업의 책임

| 작업 | 입력 | 출력 | 서버가 확인하는 것 |
| --- | --- | --- | --- |
| 주장 추출 | 발언 전문·개수 제한 | 원문 주장·원문 문맥·반복 횟수 | 주장·문맥이 전문에 있는지, 중복 여부, 발언 위치 연결. 빈 배열은 정상적인 주장 없음으로 처리한다. |
| 관계 판정 | 주장·문맥·영상 제목/게시일·번호가 있는 근거·발행처/날짜/자료 범위 | 일치/불일치/부족·사유·근거별 인용/이유 | 인용 번호·인용문이 모델에 보낸 해당 자료 범위에 있는지, 일부 인용 검증 실패 시 전체 결론 강등, 부족이면 인용 제거. |

프롬프트는 발언·자료 안의 명령을 데이터로만 다루고 주체·대상·시점·부정·조건·수치 단위를 보존하도록 요구한다. 게시일을 사건 발생일로 단정하지 않으며, 같은 정책의 다른 기간 자료만 있으면 `time_mismatch`를 우선한다. 독립 출처와 정정 여부도 확인하도록 요구한다.

### 코드로 보장되는 것과 남은 한계

문자열 인용 검증은 인용의 존재를 확인한다. 그 문장이 주장의 모든 조건을 지지하는지, 출처가 신뢰할 만한지, 서로 독립적인지는 이 검사만으로 증명되지 않는다. 문맥 전달도 모든 STT 오류를 바로잡는 기능이 아니다. 반복 횟수는 모델 출력이며 모든 반복 위치를 별도로 추출하는 기능은 남아 있다.

현재 검색 제공자는 제목·요약문을 반환한다. 실제 판정 입력에는 `content_scope=search_excerpt`라고 명시하며 원문을 확보한 것처럼 부르지 않는다. 프롬프트는 원문/독립성을 확인하지 못하면 유보하도록 요구하지만, 서버에는 원문 수집과 독립성 강제 검증이 아직 없다. 이 상태에서 과거의 일치 판정 건수가 줄어들 수 있다. 단순히 판정 수를 늘리려고 프롬프트의 유보 기준을 낮추지 않는다.

공개 전 우선 작업은 원문 수집, 검색 발췌와 원문 구분, 동일 원문 재전송 묶기, 충분성 검증, 실제 고정 영상 평가다. 자료가 충분하지 않은 현재 상태를 숨기기 위한 STT 자동 교정이나 모델 변경부터 하지 않는다.

## 로컬 회귀 검사

```bash
.venv/bin/python -m pytest -q
```

167건 통과, 기존 의존성 deprecation 경고 2건. 새 검사 17건은 문맥 전달·정상 빈 추출·입력 뒤쪽 손실·잘못된 인용/번호·자료 표시 누락·메타데이터 시점·단계/경과/집계 등을 다룬다. 가짜 모델을 사용하는 회귀 테스트는 모델의 의미 판정 정확도를 측정하지 않는다.

## 실제 DeepSeek 고정 사례 평가

합성한 '가상시'의 발언·자료를 사용한다. 개인정보나 실제 기사를 외부로 전송하지 않는다. [고정 사례](../tests/fixtures/prompt_cases.json) 11건을 기준으로 추출 내용과 판정·사유·인용을 점검한다. 미래에 비교할 때 기대값을 출력에 맞춰 고치지 않는다.

```bash
.venv/bin/python scripts/evaluate_prompts.py
.venv/bin/python scripts/evaluate_prompts.py --live --env-file .env
```

첫 명령은 목록 확인만 하며 외부 호출은 없다. `--live`는 설정된 LLM을 실제 호출하며 비용이 발생할 수 있다. 외부 호출은 동시 2건, 모델 `deepseek-chat`, temperature 0으로 점검했다. 결과는 기본 `results/prompt-evaluation.json`에 저장하며 실제 사용 모델·프롬프트 버전·Git HEAD·dirty 상태·사례별 출력을 포함한다. 평가 도중 프롬프트·기대값을 수정하지 않는다.

| 버전 | 결과 | 관측 |
| --- | --- | --- |
| 2026-09-10.2 | 10/11 | 시점이 다른 자료에서 판정은 부족으로 맞았으나 사유가 not_direct였다. |
| 2026-09-10.3 | 11/11 | 같은 대상의 다른 기간 자료는 time_mismatch를 우선하도록 명시한 뒤 동일 11건을 재실행했다. |

원시 결과: [v2](evaluations/2026-09-10-prompt-v2.json), [v3](evaluations/2026-09-10-prompt-v3.json). 두 실행 모두 기반 HEAD `8a11b46` 위의 작업 트리에서 진행했으므로 버전과 변경 내용을 함께 확인한다.

사례 구성은 주장 없음·문맥·부정·추출 프롬프트 인젝션 4건, 원문 기반 일치·불일치·검색 발췌 한계·시점 불일치·부분 확인·충돌·판정 프롬프트 인젝션 7건이다. 양성 판정 사례의 `original`은 테스트 작성자가 제공한 가상 원문이다. 현재 검색 코드가 원문을 수집했다는 의미가 아니다. 추출 검사는 실제 추출 함수로, 판정 검사는 고정 자료를 프롬프트에 직접 넣어 평가했다.

11/11은 이 작은 고정 사례 한 차례의 결과다. 실제 영상 정확도, 해커톤 M-08 완결성 70% 통과, 일반적인 인젝션 방어 성능이나 모델 선택의 우수성을 뜻하지 않는다. 동일 사례 반복은 회귀 검사용이며, 다음 품질 판단에는 별도 미사용 사례와 실제 영상 정답 세트가 필요하다.

## docs PR #7에 공유할 변경·차이

이번 검토 결과를 팀에 공유할 때 아래 내용을 근거로 사용한다. 아직 외부 댓글을 전송하지 않았다.

- DeepSeek·네이버 통합은 기존 구현이다. 이번 변경은 문맥·게시일 전달, 인용 검증과 화면 응답의 누락 보완이다.
- 검색 제목·요약문 대조를 원문 검증 완료로 기록한 과거 표현은 정정이 필요하다. 현재 원문 수집·독립 출처 확인은 구현되지 않았다.
- 새 프롬프트는 이 한계를 명시하고 유보하도록 요구한다. 데모에서 기대하는 판정 비율은 실제 원문 확보 후 다시 측정해야 한다.
- 내부 연동용 배포 구성은 M4 맥미니·OrbStack·기존 cloudflared 환경으로 준비했다. 실제 API/FE 주소와 공개 검수는 미완료다.
